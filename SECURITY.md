# Security Policy

## Reporting a security issue

Please do **not** disclose suspected security vulnerabilities publicly in a GitHub Issue.

If you identify a vulnerability affecting the SecAIQ website, its tools, or material distributed through this repository, use a private reporting channel made available by SecAIQ.

If no private GitHub security-advisory channel is available yet, contact SecAIQ through the contact method published on:

https://secaiq.com/

## What to include

Please include, when applicable:

- the affected component or URL,
- a concise description of the issue,
- steps needed to reproduce it,
- expected versus observed behavior,
- potential security impact,
- screenshots or logs with sensitive information removed.

## Please avoid

- accessing data that does not belong to you,
- degrading service availability,
- attempting persistence,
- publishing credentials or secrets,
- publicly disclosing a vulnerability before SecAIQ has had a reasonable opportunity to review it.

## Guidance-content issues

If the issue is a correction, ambiguity, broken link, or improvement to the security guidance itself rather than a vulnerability, opening a normal GitHub Issue or pull request is appropriate.
