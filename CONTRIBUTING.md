# Contributing to SecAIQ AI Security Guidance

Thank you for helping improve this guidance.

## Good contributions

Contributions are especially useful when they:

- improve technical accuracy,
- make a recommendation clearer or more actionable,
- identify an unsafe ambiguity,
- add a missing security consideration,
- improve machine-readable consistency,
- fix broken links, grammar, or terminology.

## Before submitting

1. Keep guidance concise and implementation-neutral where possible.
2. Prefer security principles over vendor-specific product instructions.
3. Distinguish deterministic controls from model-behavior recommendations.
4. Do not add real credentials, personal data, secrets, exploit payloads, or sensitive production details.
5. Preserve the intent of the corresponding SecAIQ guidance.

## Pull requests

A pull request should explain:

- what changed,
- why it changed,
- whether the change affects machine-readable files,
- whether it changes the meaning of an existing recommendation.

Material guidance changes should update both the Markdown source and the JSON/YAML representations when applicable.

## Style

Use direct, plain English.

Prefer:
- "Do not expose credentials."

Avoid:
- overly abstract or promotional language,
- unexplained acronyms,
- claims that a control guarantees security.
